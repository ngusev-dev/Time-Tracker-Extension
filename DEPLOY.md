# Развёртывание

Проект состоит из двух частей:

- **api** — NestJS + GraphQL, запускается на сервере в Docker. Миграции БД применяются автоматически при старте контейнера.
- **client** — браузерное расширение. Собирается локально и загружается в браузер вручную.

---

## 1. API на сервере

### Настроить переменные окружения

Все переменные задаются в `docker-compose.yml` в секции `environment`:

| Переменная       | Описание                                                                        |
| ---------------- | ------------------------------------------------------------------------------- |
| `DATABASE_URL`   | Строка подключения к PostgreSQL                                                 |
| `MAIL_HOST`      | SMTP-сервер (`smtp.resend.com`)                                                 |
| `MAIL_PORT`      | Порт SMTP (`465`)                                                               |
| `MAIL_USER`      | Пользователь SMTP (`resend`)                                                    |
| `MAIL_PASSWORD`  | API-ключ Resend — без него не будут отправляться письма восстановления пароля   |
| `SESSION_SECRET` | Ключ подписи сессионных cookie — длинная случайная строка                       |
| `COOKIE_SECURE`  | `"true"`, если API доступен по HTTPS; `"false"` — только для локального запуска |

## 2. Расширение (client)

Расширение собирается локально, пользователям раздаются готовые файлы: zip для Chrome и подписанный `.xpi` для Firefox.

### 2.1. Настроить окружение

Файлы окружения не хранятся в git. Создайте их из шаблона:

```sh
cd client
npm i
cp .env.example .env.production    # для сборок (build:*)
cp .env.example .env.development   # для разработки (dev:*)
```

В `client/.env.production` укажите адрес API на сервере (без `/graphql` и без `/` в конце):

```
VITE_API_URL=https://api.example.com
```

Из этого адреса берутся и URL для запросов, и `host_permissions` в манифесте — без них браузер не пустит расширение к API.

### 2.2. Ключи для подписи Firefox (один раз)

Обычный Firefox устанавливает навсегда только подписанные расширения. Подпись бесплатная: сборка отправляется на addons.mozilla.org (AMO) как **unlisted** — её подписывают, но не публикуют в каталоге.

1. Зарегистрироваться на [addons.mozilla.org](https://addons.mozilla.org/developers/).
2. Получить API-ключи на странице [Manage API Keys](https://addons.mozilla.org/developers/addon/api/key/): **JWT issuer** и **JWT secret**.
3. Вписать их в `client/.env.production`:

   ```
   WEB_EXT_API_KEY=<JWT issuer>
   WEB_EXT_API_SECRET=<JWT secret>
   ```

`.env.production` в `.gitignore` — не коммитьте ключи. В сборку расширения они не попадают: Vite встраивает только переменные с префиксом `VITE_`.

> `gecko.id` в `client/manifest.config.ts` привязывает расширение к вашему аккаунту AMO. После первой подписи его менять нельзя — иначе Firefox сочтёт новую версию другим расширением.

### 2.3. Собрать релиз

1. Поднять `version` в `client/manifest.config.ts` (`1.0.0` → `1.0.1`). AMO не подписывает одну версию дважды.
2. Собрать:

   ```sh
   cd client
   npm run build:chrome    # → web-ext-artifacts/time-tracker-chrome-<версия>.zip
   npm run build:firefox   # → web-ext-artifacts/*.xpi (подпись на AMO, обычно несколько минут)
   ```

`build:chrome` пересобирает `client/dist` — остановите `npm run dev:chrome`, если он запущен, иначе dev-сервер и сборка перезапишут друг друга.

> Сборка минифицирована, поэтому AMO может запросить исходники. Тогда приложите архив папки `client` без `node_modules` и `dist*` в кабинете разработчика.

### 2.4. Установить у пользователей

Отправьте zip для Chrome и `.xpi` для Firefox вместе с инструкцией ниже.

**Firefox (140+):**

1. Перетащить `.xpi` в окно Firefox и нажать **Добавить**.
2. Открыть `about:addons` → Time Tracker → вкладка **Разрешения** и включить доступ к хосту API.

> В Firefox разрешения на хосты не выдаются при установке. Пока доступ к API не включён, запросы блокируются CORS.

Обновление — установить новый `.xpi` тем же способом, поверх старого.

**Chrome / Edge / Яндекс Браузер:**

1. Распаковать zip в постоянную папку, например `C:\Extensions\time-tracker` (не в «Загрузки» — если папку удалить, расширение пропадёт).
2. Открыть `chrome://extensions` (в Edge — `edge://extensions`) и включить **Режим разработчика**.
3. Нажать **Загрузить распакованное расширение** и выбрать эту папку.

Обновление — заменить содержимое той же папки файлами из нового zip и нажать ↻ на карточке расширения. Логин и данные сохраняются, пока папка остаётся той же.

> Чтобы ставить расширение в Chrome без режима разработчика, нужна публикация в [Chrome Web Store](https://chrome.google.com/webstore/devconsole) (разовый взнос $5, можно как unlisted — доступ только по ссылке).

## 3. Локальная разработка

API для разработки берётся из `client/.env.development`.

**Chrome** — с HMR:

```sh
npm run dev:chrome
```

Открыть `chrome://extensions` → **Режим разработчика** → **Загрузить распакованное расширение** → папка `client/dist`. Dev-сервер должен быть запущен, пока расширение открыто.

**Firefox** — без HMR. Dev-сервер Vite в Firefox не работает: страницы расширения в dev-режиме crxjs отдаёт через service worker, а у расширений Firefox его нет. Вместо этого — пересборка с автоперезагрузкой, в двух терминалах:

```sh
npm run dev:firefox   # пересобирает dist-firefox при изменениях
npm run run:firefox   # запускает Firefox с расширением и перезагружает его после пересборки
```

`run:firefox` открывает отдельный чистый профиль Firefox, поэтому доступ к хосту API в нём нужно включить один раз: `about:addons` → Time Tracker → **Разрешения**.
